# Environment configuration

BedrockNexus Plugins separates browser-visible Next.js values from server-only
Convex deployment secrets. Development, staging, and production must use
separate Convex deployments, OAuth applications, GitHub Apps, and secrets.

## Next.js `.env.local`

| Variable | Secret | Purpose |
| --- | --- | --- |
| `CONVEX_DEPLOYMENT` | No | Convex CLI deployment selector generated by `bunx convex dev` |
| `NEXT_PUBLIC_CONVEX_URL` | No | Convex cloud URL bundled into the client |
| `NEXT_PUBLIC_CONVEX_SITE_URL` | No | Convex HTTP site URL used by Better Auth |
| `DOWNLOAD_REDIRECT_SECRET` | Yes | Authorizes the Next.js download route to record a redirect |

Start with `.env.example`. Never commit `.env.local`.

## Convex deployment variables

Set these with `bunx convex env set NAME VALUE` against the intended deployment:

| Variable | Secret | Purpose |
| --- | --- | --- |
| `SITE_URL` | No | Allowed application origin for Better Auth |
| `BETTER_AUTH_SECRET` | Yes | Better Auth signing secret |
| `GITHUB_CLIENT_ID` | No | GitHub OAuth application client ID |
| `GITHUB_CLIENT_SECRET` | Yes | GitHub OAuth application client secret |
| `GITHUB_APP_ID` | No | Repository GitHub App identifier |
| `GITHUB_APP_CLIENT_ID` | No | Repository GitHub App client ID |
| `GITHUB_APP_CLIENT_SECRET` | Yes | Repository GitHub App client secret |
| `GITHUB_APP_PRIVATE_KEY` | Yes | Repository GitHub App PEM private key |
| `GITHUB_APP_WEBHOOK_SECRET` | Yes | Verifies GitHub webhook signatures |
| `GITHUB_APP_SLUG` | No | Repository GitHub App slug |
| `DOWNLOAD_REDIRECT_SECRET` | Yes | Must exactly match the Next.js value |

Generate secrets with a cryptographically secure generator. Use different
values in every environment and rotate a value immediately if it may have been
logged, pasted into an issue, or committed.

The GitHub private key may be stored with literal `\n` separators. The backend
restores PEM line breaks before constructing the Octokit client.

## CI

CI uses non-production placeholder Convex URLs so `next build` can validate the
application without receiving deployment secrets. CI does not authenticate,
call protected Convex functions, or produce a deployable artifact.

## Production

Set the public Convex values in the deployment platform at build time because
Next.js bundles `NEXT_PUBLIC_*` variables into browser assets. Store all
server-only values in the matching Convex deployment, except
`DOWNLOAD_REDIRECT_SECRET`, which is intentionally shared with the Next.js
server route.
